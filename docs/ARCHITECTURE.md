# Архитектура «Муравьишки: Пиксельная охота»

Документ отражает проверенную структуру на 12 ноября 2026; перед изменениями сверяй актуальные файлы main.

## Web/PWA приложение
- index.html — DOM-каркас.
- src/app.js — UI, визуализация, координация игровых действий и жизненный цикл партии.
- src/game.js — чистая игровая модель, правила, генерация поля и очередь боксов.
- src/ant-animation.js — чистые функции фаз движения, ограниченной задержки запуска, паузоустойчивых часов и Catmull–Rom позы муравья.
- src/campaign.js — правила последовательного открытия полянок.
- src/styles.css — адаптивный интерфейс и слои визуализации.
- Vite; Node.js 22+; npm test и npm run build.

## Игровая модель
- Поле 35×35.
- Пять стартовых слотов; модель очереди 3×3 сохраняется, интерфейс показывает три активные колонки и превью следующих двух боксов.
- Муравей собирает только блок своего цвета, один блок за рейс.
- Доступность блока определяется flood fill пустых клеток от внешней границы: внутренние полости не открывают блок; можно собирать только наружный слой.
- Цель не должна резервироваться одновременно двумя муравьями.
- Поражение — только когда все пять слотов заняты и допустимых ходов больше нет.

## KT-042 — внешний слой и визуал
- `getExposedPixels` обходит пустые клетки, связанные с внешней границей; только соседние с этой областью блоки доступны для сбора.
- Поиск волны использует единый расчёт открытых клеток, без повторного flood fill на каждого муравья.
- Очередь пополнения берёт длину колоды выбранного уровня, а не базовой лягушки.
- Игровое поле рисуется объёмными градиентными блоками с бликами, тенями и подсветкой открытого слоя; CSS-поверхности получили более выраженный мультяшный объём.

## Рендерер муравьёв — KT-035
- Все активные муравьи рисуются на общем canvas #ant-layer.
- Один requestAnimationFrame loop обновляет все траектории.
- activeAnts хранит состояние каждого активного рейса; workerPromises управляет игровыми обещаниями и слотами.
- Индивидуальные задержки, кривые outbound/return, pickup и завершение остаются независимыми.
- Один общий clearRect выполняется на кадр вместо отдельной полноразмерной очистки на каждого муравья.
- Спрайты кэшируются по цвету, переносимому блоку и фазе походки.
- KT-079: `getTrailPose` вычисляет прежнюю позицию и аналитическую касательную одной выборкой; `renderAntFrame` больше не вызывает три отдельных `trailPoint` для каждого муравья.
- KT-095: каждый активный муравей хранит собственные `phaseFrame` и `pose`; `getAntTripFrame` и `getTrailPose` заполняют переданные буферы, поэтому общий RAF-цикл не создаёт новые объекты результата на каждом кадре. Поля буферов полностью перезаписываются и для вырожденных маршрутов.
- Сокращение вычислений подтверждено анализом кода и регрессионными тестами; реальный FPS/CPU на Android ещё нужно измерить.
- Изменение размеров canvas учитывает devicePixelRatio; траектории рассчитываются в логических координатах оболочки.
- Это архитектурное сокращение DOM/canvas и RAF overhead, а не измеренный benchmark. Реальный FPS/CPU на мобильном устройстве ещё нужно измерить.

## Пауза анимаций при скрытой странице — KT-076
- `createPausableClock` задаёт логическое монотонное время, которое перестаёт увеличиваться между событиями `visibilitychange: hidden` и `visible`.
- Общие часы используют рейсы муравьёв, походка спрайта, pickup-кольца, перемещение бокса в слот и уход боксов на конвейер.
- Временные метки `requestAnimationFrame` переводятся в логическое время; исходный timestamp остаётся только для ограничения частоты кадров.
- При возврате вкладки анимации продолжаются с прежней фазы, а не перескакивают к завершению из-за времени в фоне.
- Логика выбора, резервирования пикселей, лимиты слотов, длительность активного рейса и правила победы/поражения не меняются.
- Unit и DOM-contract тесты проверяют заморозку, возобновление, повторные события и подключение всех трёх RAF-циклов. Реальный FPS и поведение на физическом устройстве не измерялись.

## Остальные анимации
- Анимация перемещения бокса по конвейеру и отгрузки использует отдельные временные canvas. Их немного, и они не создаются на каждого муравья.
- DOM/CSS и Web Animations API используются для интерфейсных переходов.

## Сохранение
- Незавершённая партия намеренно не сохраняется.
- В localStorage хранится только список завершённых полянок кампании (ants-campaign-progress).
- src/storage.js и сериализация состояния в src/game.js — legacy-код; текущий src/app.js их не использует.

## PWA и CI
- public/manifest.webmanifest — манифест.

- .github/workflows/pages-deploy.yml — тесты, production build и GitHub Pages deploy.

## Границы
- Публичная игра сейчас Web/PWA.
- Godot — отдельный прототип в этом репозитории.
- Capacitor config не означает, что APK собран или опубликован.
- Разрешение на прямые изменения main относится только к MaiklLX/Ants-Pixel-Hunt.


## KT-043 — производительность и тактические боксы
- buildIncoming распределяет общий бюджет цвета по разноразмерным партиям; сумма строго равна количеству блоков цвета на карте.
- findAntWave принимает maxMoves и планирует только размер доступного окна; браузер поддерживает не более 36 активных рейсов одновременно.
- ant-layer ограничен примерно 30 кадрами/с и DPR 1.5; фазы похода по-прежнему вычисляются по timestamp, поэтому пропуск кадра не сбивает тайминг.
- После подбора renderBoardAfterPickup очищает одну клетку и дорисовывает только новые экспонированные клетки. renderChoices не вызывается на каждый pickup.
- Анимации боксов и отгрузки ограничены примерно 30 кадрами/с; временные canvas используют DPR до 1.5.
- CSS-стили crate/conveyor дают объём, ролики и блик без дополнительных DOM-узлов.
- Это целевые оптимизации по числу операций, а не измеренный benchmark: фактический FPS на Android ещё требуется измерить.
