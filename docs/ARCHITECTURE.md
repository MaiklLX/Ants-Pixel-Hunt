# Архитектура «Муравьишек: Пиксельная охота»

Документ описывает фактическую структуру репозитория на baseline KT-034 / commit f0daf6b3d0928c6b9f34497c7ecca5b386800af2. Перед архитектурными изменениями перепроверь файлы: реализация может измениться.

## Основные слои

### 1. Браузерное приложение и интерфейс
- index.html — DOM-каркас приложения и точки подключения интерфейса.
- src/app.js — связывает DOM, модель игры, сохранение и визуальные эффекты.
- src/styles.css — оформление, адаптивная компоновка и визуальные состояния.
- vite.config.js — конфигурация Vite и production-сборки.
- package.json — команды npm test, npm run build, npm run serve; требуется Node.js 22+.

### 2. Чистая игровая модель
- src/game.js содержит правила и состояние головоломки без DOM-рендеринга.
- Генерирует стартовую авторскую пиксельную картинку и очередь боксов.
- Определяет доступность блока, выбор бокса, поиск волн муравьёв, захват блока, освобождение слота и поражение.
- Поддерживает сериализацию/восстановление сохранённой партии.
- tests/game.test.js проверяет игровую модель средствами Node test runner.

Ключевые инварианты:
- один муравей переносит один блок;
- муравей собирает только цвет своего бокса;
- цель не должна одновременно резервироваться двумя муравьями;
- поражение возможно только при пяти занятых слотах, отсутствии допустимого хода и наличии оставшихся блоков;
- победа — поле полностью очищено.

### 3. Анимация и отрисовка
- Основное поле рисуется в canvas.
- Для слоя муравьёв используется canvas поверх игрового интерфейса.
- Визуальные спрайты муравьёв создаются и кэшируются по цвету, состоянию переноски и фазе походки.
- Траектории строятся как индивидуальные наборы точек; промежуточная позиция вычисляется по сглаженной кривой.
- Анимации боксов и UI используют DOM/CSS, Web Animations API и отдельные worker-layer canvas.
- Координаты зависят от размеров DOM-элементов и оболочки; при оптимизации обязательно учитывать resize, devicePixelRatio и разные размеры экрана.

Это описание фиксирует наблюдаемую структуру, но не является доказательством оптимальной производительности. KT-035 должна измерить фактическую стоимость создания canvas, количества активных кадров, вычисления траекторий и перерисовки.

### 4. Локальное сохранение
- src/storage.js использует IndexedDB (ants-pixel-hunt, store saves, key level-1).
- Если IndexedDB недоступен или операция не удалась, используется localStorage.
- Схема сохранения и миграция должны оставаться обратно совместимыми. Не очищать сохранения пользователя при обычном обновлении.

### 5. PWA и публикация
- public/manifest.webmanifest — PWA manifest.
- public/service-worker.js — кэш оболочки и статических ресурсов; версия cache key должна обновляться при необходимости, чтобы пользователи получили новые bundle-файлы.
- .github/workflows/pages-deploy.yml выполняет install → gameplay tests → production build → upload artifact → deploy GitHub Pages.
- .github/workflows/web-check.yml выполняет browser tests и production build для предусмотренных событий.
- .github/workflows/godot-check.yml отдельно проверяет сохранённый Godot-проект.
- Успешный Godot workflow не подтверждает идентичность Godot- и Web-версий; успешная сборка не равна тесту на физическом устройстве.

## Границы архитектуры
- Текущая публичная версия — Web/PWA.
- Godot-прототип — отдельный сохранённый технический слой.
- Capacitor — подготовленная Android-оболочка, но наличие конфигурации не доказывает готовность APK или публикацию в магазине.
- Не переносить код, разрешения и решения из Game-ANTS автоматически в этот проект.

## Направление развития
Следующий технический фокус — KT-035: производительность колонии и масштабирование анимации. Сначала измерение и воспроизводимый сценарий, затем оптимизация с сохранением индивидуальности движения, переносимого кубика и независимости боксов.
