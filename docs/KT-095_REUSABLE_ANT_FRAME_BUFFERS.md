# KT-095 — переиспользование буферов кадра муравьёв

**Дата:** 12 ноября 2026.  
**Статус:** изменения исходников и регрессионные проверки записаны в `main`; полный CI и публикация для итогового SHA пока не подтверждены.

## Причина

После KT-035 колония уже использует один общий canvas и один `requestAnimationFrame`. После KT-079 позиция и направление муравья вычисляются одной выборкой Catmull–Rom. Однако `getAntTripFrame()` и `getTrailPose()` всё ещё возвращали новый объект на каждом кадре для каждого активного муравья.

При предельных 36 одновременно движущихся муравьях и целевой частоте около 30 FPS это могло создавать до примерно 2160 короткоживущих объектов результата в секунду. Это оценка по лимитам кода, а не измеренный профиль памяти или benchmark.

## Изменение

- `getAntTripFrame(..., out)` теперь умеет записывать все пять полей фазы в переданный объект результата.
- `getTrailPose(points, progress, out)` записывает координаты и угол в переданный объект, включая пустой и одноточечный маршруты.
- Каждый активный муравей получает собственные `phaseFrame` и `pose` при создании рейса.
- `renderAntFrame()` повторно использует эти два объекта на каждом кадре вместо создания новых.
- Если вызывающий код не передаёт `out`, обе функции сохраняют прежнее удобное поведение и возвращают новый объект.
- Математика Catmull–Rom, направление, индивидуальные траектории, задержки, pickup, обратный путь, скорость и лимит муравьёв не менялись.

## Регрессионные проверки

- Unit test проверяет повторное использование одного объекта фазы в состояниях ожидания, outbound, return и завершения.
- Unit test проверяет повторное использование pose-объекта, изменение координат, конечность значений и сброс буфера для пустого/одноточечного маршрута.
- DOM-contract test проверяет, что RAF renderer передаёт `ant.phaseFrame` и `ant.pose`, а буферы создаются один раз на рейс.
- Точечный Node.js harness для новых фазовых и pose-проверок выполнен локально: **PASS**.
