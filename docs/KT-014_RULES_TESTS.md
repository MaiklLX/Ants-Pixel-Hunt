# KT-014 — автоматические проверки игровых правил

## Цель

Зафиксировать базовые правила в исполняемых headless-проверках, чтобы изменения в интерфейсе и анимациях не ломали механику пиксельной охоты незаметно.

## Проверки

- Пиксель на границе поля доступен.
- Пиксель, окружённый со всех четырёх сторон, недоступен.
- Освобождение хотя бы одного ортогонального соседа открывает пиксель.
- Поиск возвращает только доступный пиксель нужного цвета.
- Если подходящего цвета нет, поиск возвращает пустую координату.
- Поражение наступает при пяти занятых ячейках, отсутствии доступного хода и оставшихся пикселях.
- Открытие одной стороны заблокированного пикселя отменяет поражение.
- Пустой контейнер не считается доступным ходом; свободная ячейка и пустое поле исключают поражение.
- Наличие хотя бы одного доступного хода предотвращает поражение.
- Наличие свободной пусковой ячейки предотвращает поражение.

## Запуск

Проверки выполняются в Godot 4.3 без графического окна:

```bash
godot --headless --path . --script res://tests/rules_smoke.gd
```

GitHub Actions запускает этот тест после импорта ресурсов и перед коротким smoke test главной сцены.

## Граница проверки

Тесты вызывают реальные методы игровой сцены, а не отдельную копию алгоритма. Они не заменяют ручное тестирование анимаций, касаний и масштабирования на Android, iOS и Web/PWA. Результат считается подтверждённым только после успешного выполнения workflow.
