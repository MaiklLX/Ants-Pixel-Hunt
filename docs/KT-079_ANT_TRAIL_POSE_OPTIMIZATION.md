# KT-079 — оптимизация выборки позы муравья

**Статус:** код, unit/DOM tests, production build и Pages deploy подтверждены.  
**Дата:** 11 ноября 2026.  
**Кодовый commit:** `e7a82e5ff1b863bbb2782046d3946c235fe9703a`.

## Причина

Общий renderer KT-035 уже использовал один canvas и один requestAnimationFrame для всей колонии. Но в каждом кадре для каждого движущегося муравья приложение трижды вычисляло одну Catmull–Rom кривую: текущую позицию, точку немного до неё и точку немного после неё. Последние две точки нужны были только для оценки направления корпуса.

## Изменение

- В `src/ant-animation.js` добавлена чистая `getTrailPose(points, progress)`.
- Она вычисляет прежнюю Catmull–Rom позицию и аналитическую производную этой же кривой.
- `src/app.js` теперь получает `{x, y, angle}` одним вызовом и передаёт позу в существующий `drawAnt`.
- Старый локальный `trailPoint` удалён.
- Точки маршрута, амплитуда извилистости, задержки старта, outbound/return durations, pickup, переносимый блок, лимит 36 муравьёв и частота около 30 FPS не менялись.

## Ожидаемый эффект и границы измерений

На каждого муравья за кадр число выборок положения сокращено с трёх до одной. Вместе с аналитической касательной число скалярных полиномиальных вычислений позиции/направления уменьшается с шести до четырёх (около 33%). Также исчезают две временные точки и объект касательной.

Это оценка по структуре кода, а не результат профилирования. FPS, CPU и батарея на физическом телефоне не измерялись.
