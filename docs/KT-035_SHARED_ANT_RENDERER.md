# KT-035 — единый рендерер колонии и производительность

**Статус:** реализация внесена в main; GitHub Actions для code commit ожидают выполнения на момент записи.  
**Дата:** 10 ноября 2026.

## Что выявил аудит

До изменения каждый муравей создавал отдельный полноразмерный canvas-элемент, отдельный контекст и собственный requestAnimationFrame loop. При групповой отправке это означает потенциально десятки или сотни canvas и одновременно работающих RAF callbacks. Каждый отдельный canvas очищал всю площадь игровой оболочки на каждом кадре, хотя рисовал только одного муравья.

Это реальный структурный источник лишней работы при больших волнах. Профилирование на физическом мобильном устройстве в рамках этой задачи не выполнялось; количественный FPS/CPU benchmark не заявляется.

## Что изменено

- Все муравьи теперь используют уже существующий общий canvas #ant-layer.
- Введён единый renderAntFrame(timestamp): один requestAnimationFrame loop обновляет и рисует все активные траектории.
- Активные муравьи хранятся в activeAnts; их независимые задержки старта, индивидуальные кривые, момент подбора блока и обратный путь сохранены.
- Вместо N полноэкранных очисток выполняется одна очистка общего canvas на кадр.
- Удалено создание и удаление отдельного DOM canvas для каждого муравья.
- Координаты очистки учитывают логический размер canvas и devicePixelRatio.
- Общий слой поднят над полем, чтобы сохранить прежний визуальный порядок.
- Вынесена чистая функция getAntTripFrame в src/ant-animation.js и добавлены тесты фаз движения.

## Результат и дальнейшая работа

Архитектура анимации стала масштабироваться лучше по числу DOM canvas и RAF loops: теперь на всю колонию приходится один canvas и один общий цикл кадров. Следующий шаг после CI — проверить поведение на публичной сборке, включая несколько одновременно заполненных слотов, перенос кубика, независимость муравьёв, изменение размера окна и возврат в меню.
