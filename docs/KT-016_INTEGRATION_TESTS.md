# KT-016 — интеграционные тесты полного цикла

## Задача

Проверить не отдельные функции, а последовательную работу пяти пусковых ячеек на реальной игровой сцене.

## Изменения

- В игровой сцене появился журнал фактического сбора `resolution_log`: номер слота, цвет и координаты снятого пикселя.
- Журнал очищается при перезапуске уровня.
- Метод `_resolve_all_slots` получил параметр `animate`. В обычной игре он включён по умолчанию. Для headless-интеграционных тестов анимации отключаются, но используется тот же самый алгоритм выбора цели, обхода слотов, повторных проходов, списания муравьёв и определения результата.
- Добавлен сценарий, который подтверждает приоритет слота 1 перед слотом 5, когда оба контейнера могут собирать пиксели.
- Добавлен сценарий, где контейнер в первом слоте сначала ждёт закрытый пиксель, контейнер в пятом слоте снимает окружающие пиксели, после чего первый слот получает ход на следующем проходе.
- Проверяется полная очистка поля и переход в состояние победы.

## Запуск

```bash
godot --headless --path . --script res://tests/rules_smoke.gd
```

Тесты запускаются в GitHub Actions на Godot 4.3.

## Ограничения

- Headless-режим проверяет логику, но не качество визуальных анимаций.
- До успешного результата GitHub Actions нельзя считать тесты выполненными.
- Отдельно остаётся ручная проверка Android, iOS и Web/PWA.
